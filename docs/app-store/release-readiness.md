# App Store release checklist

Updated October 10, 2026 against `origin/main` at `d88d9749ddbf087e75346e6fffd0e64f11d7af03`, version 1.0.4, source build 16. This is a submission checklist, not a claim of App Store availability or signed Production readiness. See [the final audit](../final-release-readiness.md) for evidence and proof limits.

## Remaining release blockers

- [ ] **Production lifecycle access policy.** An authorized human must disable World Read on `FamilyLifecycleAuthority`, then verify authenticated read/create and creator-only write against [the authoritative contract](../family-lifecycle-authority.md). The October 10 human inspection confirmed the type and fields, but recorded World Read enabled. Do not redeploy the schema solely because an older report says the type was missing.
- [ ] **Signed household validation.** Validate the final candidate with two physical devices and separate iCloud accounts: parent/child invitations, cold/warm QR and link acceptance, exact profile binding, completion sync, offline retry, relaunch, account membership recovery, read-only/revoked access, and older-client write refusal after an occurrence-aware action. Record the build and OS versions with each result. Follow the existing [invitation](../production-invitation-package/report.md) and [membership](../production-membership-recovery/report.md) procedures.
- [ ] **Deletion and generation safety.** After correcting the lifecycle roles, perform the authorized two-account interruption, Finish Deleting, relaunch, account-switch, revoked-child Reset App, and same-parent/same-children fresh-family checks in [the deletion procedure](../delete-all-earned-it-data-implementation-report.md). Use an approved disposable household. Never test by deleting a real family's records.
- [ ] **Final signed artifact.** Through the authorized release workflow, archive and validate the candidate with the current required SDK. Inspect its actual identity/version/build, Production iCloud environment, container and `InProcessOneTimeLinks`, embedded privacy manifest/report, app icon, camera purpose string, and iPhone/iPad support. Run `scripts/validate-release-device-family.sh` on the archive. Simulator and unsigned generic-iOS builds cannot close this item.
- [ ] **Artwork and screenshots.** Confirm commercial rights for the icon and any promotional artwork. Approve the icon's current pre-rounded tile treatment or supply an approved master. Capture accurate final-candidate screenshots with fictional data at Apple's required iPhone and iPad sizes. Do not submit `assets/earned-it-preview.png`. See [visual-assets.md](visual-assets.md).
- [ ] **Privacy, support, and review access.** Confirm the public [policy](https://github.com/jlm429/earned-it/blob/main/docs/app-store/privacy-policy.md) and [support](https://github.com/jlm429/earned-it/issues) URLs are the intended maintained destinations, enter them in App Store Connect, reconcile privacy answers with the signed archive report, and provide private review instructions/resources for sharing. The policy and in-app links already exist on `main`.
- [ ] **App Store Connect inputs and distribution.** Confirm the app record/bundle selection, updated age questionnaire and category, content rights, copyright, review contact, agreements, export compliance, territories/DSA status as applicable, price, chosen build, and release method. The draft price is Free; repository code cannot prove live pricing. Authorize TestFlight distribution and smoke-test the selected candidate before submission.
- [ ] **Integrate the final improvements.** Punt, notifications, and UI polish are separate work in progress at this audited base. After integration, validate the combined candidate, update the feature/privacy/review claims, and recapture affected screens. Do not list pending features as available or promise background push from alerts generated only when journal changes arrive.

## Final device and accessibility pass

On the integrated signed candidate, check launch/relaunch and background/foreground recovery, camera denial/manual entry, airplane-mode queued work and later convergence, longest chore/member text, largest Dynamic Type, dark mode, reduced motion, status contrast, 44-point controls, and physical-device VoiceOver reading/action order. Include iPad portrait and landscape. Existing Simulator/accessibility evidence is useful but does not prove this final combined UI or physical-device experience.

If notifications land, check explicit contextual opt-in, denial/revocation, device-local settings, privacy of lock-screen content, correct eligible-child targeting, duplicate suppression/relaunch, and the app's usable experience with alerts disabled. Genuine remote/background delivery requires separately authorized capabilities/signing and signed device proof; do not silently equate it with local alerts after refresh.

## Submission references

Apple sources were checked October 10, 2026. Recheck at submission if requirements change.

- [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/): completeness and accurate metadata, privacy/deletion, review access, notification privacy, artwork rights, and family/Kids positioning. Rule 4.5.6 permits Unicode characters rendered as emoji; embedded emoji artwork is a separate restriction.
- [Upcoming submission requirements](https://developer.apple.com/news/upcoming-requirements/): Xcode 26 or later with the corresponding iOS/iPadOS 26 SDK or later, plus the current age-rating questionnaire. Minimum deployment and build SDK are different settings.
- [Required App Store properties](https://developer.apple.com/help/app-store-connect/reference/app-information/required-localizable-and-editable-properties), [app privacy details](https://developer.apple.com/app-store/app-privacy-details/), and [managing app privacy](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy).
- [Screenshot specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications): required iPhone Dynamic Island medium-display and iPad 13-inch sets, accepted dimensions, and no alpha.
- [Notification authorization](https://developer.apple.com/documentation/usernotifications/asking-permission-to-use-notifications), [CloudKit sharing permissions](https://developer.apple.com/documentation/cloudkit/ckshare), and [database subscriptions](https://developer.apple.com/documentation/cloudkit/ckdatabasesubscription). Silent delivery requires the background-mode configuration and a subscription for the receiving account; notifications signal changes to fetch and may coalesce.

The configured no-mistakes pipeline owns validation and PR delivery. It does not authorize signing changes, Production operations, App Store Connect writes, uploads, merging, or submission.
